行旅：五个问题，一份带来源的中国入境答案

本文件是产品说明书，不是营销页。每一节都能单独阅读；数据、边界和没做到的事都写在里面。

1. 一句话定位

行旅是一个"问答式中国入境旅行助手"：用五个问题换一份带来源的证据清单，让第一次来中国的外国游客在十分钟内知道"我能不能进、要花多少钱、到了怎么开口"。

它不做预订，不做签证代办，不做实时地图。它做的是把散落在官网上的关键事实整理成可核对的结论：每条结论后面都挂来源名、原文链接、查询时间、适用范围；政策类再额外标注"官方快照，非实时法律意见"。

目标用户

  • 主要：持外国护照、计划来中国旅游或短途商务的成年人；英语为母语或可用英语沟通；不熟悉中国官方办事入口。
  • 次要：帮外国朋友规划行程的中国本地人；做入境游内容、需要快速核对政策口径的编辑。
  • 不是给：需要代办签证的人、需要实时抢票/订房的人、需要专业移民法律意见的人。

使用场景（谁、在什么情况下打开）

  1. 出发前 2–8 周，刚决定来中国，最想知道"我需不需要签证"——打开行旅，五个问题后先看入境结论。
  • 已经订好机票，想快速知道落地城市天气、人民币换汇大概是多少、一天预算要多少。
  • 落地后不会中文，菜单/路牌看不懂，或想说"洗手间在哪"——用翻译与短语库。
  • 遇到证件丢失、纠纷等紧急情况——查 12308 与使领馆入口。

    • 它刻意不做什么

    • 不承诺"一定能入境"。免签判断只给"条件性适用 / 不适用 / 未核对"三档，不给百分比，不给保证。
    • 不把旧数据当实时数据。取不到就显示"取不到"，并给官方入口。
    • 不伪造地图。没有地图 key，就不画地图，只给地址卡、经纬度和外部地图 App 跳转。

    2. 为什么存在（与官方 App、大平台的差异）

    官方工具：权威，但按"办事"组织，不按"我该怎么走"组织

    国家移民管理局的网站、移民局 12367 App、护照预约平台（s.nia.gov.cn）、故宫官网、12306，都是权威原文，但它们：

    • 各自独立，用户要自己判断"我这种情况该看哪一条"；
    • 政策页是长文，没有把"57 国 / 65 口岸 / 24 省 / 240 小时"直接对到"我这本护照 + 我要待 7 天"；
    • 多数没有英文口语化的解释，也不告诉用户"下一步去哪办"。

    行旅不替代它们：行旅把结论说清楚，然后把用户送回官方入口。所有办理动作仍发生在官方站。

    大平台（Trip.com、携程、Klook）：订得快，但不回答"资格"

    • Trip.com 首屏是"搜索卡 + 信任带"（第三方评分 4.4/5 与三条保证），强在交易闭环；它不回答"美国护照待 7 天要不要签证"。
    • 携程移动站是图标宫格 + 搜索框，交易入口密集，信息密度高；同样不把入境资格作为第一结论。
    • Klook 在本机被 WAF 拦截（HTTP 403），没有拿到首屏，不参与界面结论，只作为"交易型平台"这一类存在。

    行旅与它们的关系是前置：先回答"能不能进、要花多少、怎么开口"，再让用户去平台订。

    Google 翻译 / 高德 / Visit Japan Web

    • Google 翻译是纯工具，零引导，强在即时翻译；行旅的翻译是"旅行短语级"的，给中文 + 拼音 + 发音，并允许收藏，不追求通用翻译质量。
    • 高德网页版本机截图里地图瓦片是空白，且 Web 服务无 key 返回 INVALID_USER_KEY；行旅因此不做"看起来有地图其实没图"的假象。
    • Visit Japan Web 是先登录再给功能，行旅反过来：先给答案，再谈办理。

    口径说明：以上对比基于本项目自己的竞品调研（2026-11-05，含截图与证据等级）。另一份竞品调研结论出来后，需要对齐"信任带写法""首屏是否零引导"这两处措辞；本说明书不覆盖对方未验证的条目。

    差异一句话

    大平台卖"订"，官方站讲"规定"，行旅做"翻译规定 + 标出来源 + 送回官方"。

    3. 使用流程（五个问题）

    进入产品后不是表单，而是一段对话：一次只问一个问题，问题下面有可点的胶囊，也可以自由输入；每题都能"跳过"，答过的题都能"改答案"。

    顺序问题选项胶囊（示例）自由输入这题决定什么
    1先告诉我，你打算去哪儿？北京 / 上海 / 成都 / 西安 / 广州 / 杭州国家、城市、英文名都可天气、地址卡、预算语境
    2大概什么时候到？两周内 / 一个月内 / 1–3 个月后 / 还没定具体日期或描述行前紧迫度文案
    3打算待几天？3 天 / 5 天 / 7 天 / 10 天以上"一周""7 天""10 天以上"免签通道判定（240 小时 = 10 天）
    4你持哪国护照？美国 / 德国 / 英国 / 日本 / 新加坡 / 其他国名中英文免签判断；只用于判断，不保存
    5这次最想要什么？玩 / 吃 / 交通 / 求助（可多选）关键词是否追加交通、紧急求助结论

    答完五题（或全部跳过）后，进入结果对话流：一条条气泡给结论，每条后面挂一张可展开的证据卡。

    五个问题的设计约束：

    • 一次一问，不堆表单；上一题答完才出现下一题。
    • 胶囊 + 自由输入并存；胶囊是快捷方式，不是唯一答案。
    • 跳过不等于失败：跳过会记入答案状态，结果流照常生成，只是相应部分用"未定/未核对"表述。
    • 改答案即时重算：点"改答案"回到该题，重答后结果按新答案整体重算（见第 8 节）。

    4. 功能全景（逐屏）

    4.1 首屏问候

    • 目的：降低首次进入的陌生感，明确"这里只问五个问题"，并立刻给出第一个问题。
    • 元素：产品名"行旅"与一句话副标题；问候气泡"你好，我是行旅"；第一个问题气泡；六个目的地胶囊；"跳过这个问题"；底部输入胶囊与发送按钮。
    • 交互：点胶囊立即作答；点输入框可打字；点跳过进入下一题；发送按钮在有文字时变为可用。
    • 状态：
    • 空：不输入也可以，胶囊始终可点。
    • 加载：首屏不请求任何外部数据，所以没有加载态。
    • 错误：首屏不产生错误。
    • 成功：答完第一题，问题气泡收起为"已答"样式，下一题出现。

    4.2 问答屏（五问）

    • 目的：用最少输入拿到判定所需的四个变量（目的地、时间、天数、护照）和一个偏好（想要什么）。
    • 元素：进度标签"问题 X / 5"；问题标题；可选提示；胶囊；自由输入；"跳过"；已答题的"改答案"。
    • 交互：胶囊单击即答；多选最后一题需要点"确认"；输入框回车发送；"改答案"回到对应题，后续答案保留。
    • 状态：
    • 空：未答时只显示当前题。
    • 加载：无（本地判定，不请求外部）。
    • 错误：输入空白给出轻提示"先填一点内容，或点「跳过」"；重复作答不会覆盖。
    • 成功：五题完成，进入 4.3；已答题显示所答内容，可回改。

    4.3 结果对话流

    • 目的：把"资格、天气、汇率、预算、开放时间、证件入口、地址、交通/求助"按影响程度排序，一条一条说清楚。
    • 元素：结果气泡（标签 + 一句结论 + 一句解释）；证据卡入口；行动按钮（如"NIA 政策原文""官方预约入口""中国天气网"）；汇总条（把五个答案再复述一遍）。
    • 交互：每条证据卡可展开/收起；在桌面端展开的证据同步到右栏；表格按钮在移动端打开表格弹层，在桌面端切到右栏对应页签。
    • 状态：
    • 加载：出现一条"正在取实时数据：天气、汇率…"，此时输入被禁用。
    • 成功：约 1 秒内按顺序出现 7–9 条结论；签证与预算各带一张表。
    • 错误（单项）：某条结论写"取不到，不拿旧数据顶上"，并给官方入口；其余结论照常显示。
    • 错误（整体）：结果生成异常时给出说明气泡，不静默失败。
    • 离线：天气与汇率直接显示"设备离线"，政策快照与官方入口仍可读。

    4.4 证据卡

    • 目的：让每个结论都能被核对，而不是"看起来专业"。
    • 元素：状态标签（实时 / 官方快照 / 官方入口 / 区间估计 / 不可用）；来源名与英文名；原文链接；查询时间；页面日期（政策类）；适用范围；免责声明；失败原因（失败时）。
    • 交互：点卡片头部展开/收起；链接新窗口打开官方页面；展开状态与右栏联动。
    • 状态：
    • 成功：显示"实时"并带本次查询时间。
    • 快照：显示"官方快照"与核对日期，政策类附"非实时法律意见"。
    • 失败：显示"取不到"与原因，不显示任何旧数字。
    • 无来源：地图类明确标"地图能力说明（非数据源）"。

    4.5 两张表

    签证 / 过境通道对照表（4 行 × 5 列）

    • 列：通道 / 条件 / 停留 / 可否工作 / 官方原文（摘录）。
    • 行：240 小时过境免签；24 小时过境免签；30 天单方面免签；需提前申请签证。
    • 表下注明：摘录为摘要、非逐字原文；官方快照日期；核对日期；"非实时法律意见"。

    每日预算区间表（4 行 × 4 列）

    • 列：项目 / 经济 / 舒适 / 依据。
    • 行：住宿（元/晚）、餐饮（元/人/天）、交通（元/人/天）、门票（元/景点）。
    • 表下注明：来自公开票面与官网抽样，区间不是实时报价；不含机票与购物。
    • 交互：移动端表格可横向滚动（页面本身不横向溢出）；桌面端右栏可直接查看；表格弹层同时放两张表。
    • 状态：静态内容，无加载态；不随实时接口失败而消失。

    4.6 翻译与发音

    • 目的：让不会中文的人在菜单、路牌、打车、看病时能开口。
    • 元素：中英方向切换；输入框；译文；拼音；"发音"按钮；"复制"按钮；说明行（整句命中 / 逐词直译）。
    • 交互：英文输入给中文 + 拼音；中文输入给英文；点发音用浏览器语音读中文；语音不可用时显示可复制的拼音与原因。
    • 状态：
    • 空：未输入时发音与复制不可用。
    • 加载：本地词库查询，无加载态。
    • 错误：未收录的句子不硬编，提示"词典里没有这句；试试短语库，或把关键词拆开"。
    • 成功：整句命中标"整句"；逐词拼指标"逐词"。

    4.7 短语库

    • 目的：把高频旅行句子做成可搜索、可发音、可收藏的随身卡片。
    • 元素：搜索框；6 个分类胶囊（问路 / 点餐 / 打车 / 买票 / 求助 / 医疗）；"只看收藏"；共 252 条；每条含英文、中文、拼音；发音与收藏两个圆形按钮。
    • 交互：输入即筛选（英文、中文、拼音都可匹配）；分类切换；收藏写入本机；点发音朗读中文。
    • 状态：
    • 空：显示总数与当前匹配数。
    • 无结果：显示"没有匹配的短语"。
    • 语音不可用：与翻译相同，退化为可复制拼音。
    • 成功：列表即时更新，收藏状态持久。

    4.8 地址卡与"地图"

    • 目的：在不伪造地图的前提下，给到"这个地方在哪、怎么在手机上打开"。
    • 元素：地址卡（城市名、纬度、经度）；可开关的 SVG 坐标示意图（明确写"不是地图"）；三个打开方式：geo:、高德、Google Maps；证据卡说明为什么没有真地图。
    • 交互：点"隐藏示意图"可收起；三个按钮分别调起对应 App/网页。
    • 状态：
    • 成功：有坐标，显示经纬度与三选入口。
    • 无坐标：显示"没有内置坐标，不给假地图"。
    • 不可用：证据卡标"不可用"，说明高德无 key（INVALID_USER_KEY）、Google Maps 本机不可达。

    4.9 行前绑定清单（设计稿，未上线）

    • 目的：把"结论"变成"要做的几件事"——订票、预约、证件、网络、支付、离线包，逐项绑定到官方入口。
    • 元素（计划）：按出发日倒排的清单；每项含"什么时候做、去哪做、需要什么材料、官方链接、完成勾选"；未完成项在出发前 7 天提醒。
    • 交互（计划）：勾选保存在本机；点入口跳官方；可整单导出为文本。
    • 状态（计划）：空清单 / 已勾选 / 过期项标红 / 无官方渠道时禁用并说明原因。
    • 现状：v2 未实现此屏；目前只以"证件入口""12306""12308"三条官方入口代替。列入第 10 节路线图。

    4.10 数据说明弹层

    • 目的：一页说清"哪些是实时、哪些是快照、失败怎么办、地图为什么没有"。
    • 元素：9 个来源卡片（汇率、天气、240h 政策、免签名单、护照入口、故宫、12306、12308、预算），每张带状态、适用范围、免责声明、官方链接、核对日期；末尾"数据口径"说明。
    • 状态：静态；状态标签与结果流一致。

    5. 数据契约

    原则：所有外部请求在一个适配层收口；适配层永远返回结果对象，不抛异常给界面。 状态只有五种：ok（实时成功）、failed（失败/超时/离线）、snapshot（官方快照）、link（仅入口）、estimate（区间估计）。

    5.1 汇率（实时）

    请求：GET https://api.frankfurter.dev/v1/latest?from=CNY&to=USD,EUR,JPY

    真实响应（2026-11-05 实测）：

    {
  "amount": 1.0,
  "base": "CNY",
  "date": "2026-11-04",
  "rates": { "EUR": 0.13302, "JPY": 23.717, "USD": 0.14987 }
}
    • 字段要求：rates.USD/EUR/JPY 必须都是数字；date 为汇率日期。
    • 更新频率：欧洲央行工作日参考价，通常每个工作日更新一次。
    • 展示：100 元 ≈ 14.99 美元 / 13.30 欧元 / 2371.7 日元，并注明汇率日期与"刷卡以银行成交价为准"。
    • 失败：显示"汇率取不到，不显示旧值"+ 原因 + 中国银行牌价入口。
    • 缓存：不使用本地缓存；请求带 no-store；失败不回填旧值。
    • 地址说明：api.frankfurter.app 会 301 到 .dev 且不带 CORS 头，浏览器以 file:// 打开时会被拦；现用带 Access-Control-Allow-Origin: * 的 .dev/v1，数据同源。

    5.2 天气（实时）

    请求：GET https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current=temperature_2m,weather_code,apparent_temperature&timezone=auto

    真实响应（北京，2026-11-05 实测）：

    {
  "latitude": 39.9042,
  "longitude": 116.4074,
  "timezone": "Asia/Shanghai",
  "current": {
    "time": "2026-11-05T18:30",
    "temperature_2m": 10.8,
    "apparent_temperature": 6.3,
    "weather_code": 0
  }
}
    • 字段要求：current.temperature_2m 必须是数字；天气代码按 WMO 表译为中文（0 晴、3 阴、61 小雨、95 雷雨等）。
    • 更新频率：模型预报，通常 15 分钟–1 小时刷新。
    • 展示：北京现在 10.8°C，晴，体感 6.3°C；体感与气温差小于 2°C 时不显示体感。
    • 覆盖：只对内置的 20 个城市按经纬度取；未收录城市不编造，给中国天气网。
    • 失败：显示"天气取不到，不拿旧数据顶上"+ 官方入口。

    5.3 240 小时过境免签（官方快照）

    • 来源：https://en.nia.gov.cn/n147418/n147463/c183412/content.html（页面日期 2026-08-20，核对 2026-11-05）。
    • 快照内容：57 国普通护照、65 个指定口岸、24 个省/自治区/直辖市、停留上限 240 小时（10 天）。
    • 快照对象示例：
    {
  "source": "niaPolicy",
  "pageDate": "2026-08-20",
  "checkedAt": "2026-11-05",
  "countries": 57,
  "ports": 65,
  "regions": 24,
  "maxStayDays": 10,
  "maxHours": 240,

    • 更新频率：人工核对；政策变更后需重新抓取并改 checkedAt。
    • 判定规则（确定性）：
    • 护照在已核对名单内 + 停留 ≤ 10 天 → conditional（条件性适用），并列出其余必须同时满足的条件。
    • 停留 > 10 天 → likely（该通道不适用，改看 30 天名单或签证）。
    • 护照不在已核对名单 → unverified（未核对，不下结论）。
    • 展示：只给三档，不给百分比、不写"保证入境"。

    5.8 适配层返回对象（统一形状）

    {
  "status": "ok | failed | snapshot | link | estimate",
  "queryTime": "2026-11-05 18:31",
  "reason": "请求超时（8000ms）",
  "source": "weather",
  "data": { "...": "按来源不同" }
}
    • 超时：8 秒；用 AbortController 中止请求。
    • 离线：不发请求，直接返回 failed，原因含"offline"。
    • HTTP 非 2xx / 字段缺失 / JSON 解析失败：都是 failed，带原因。
    • 界面只消费这个对象，不直接读原始响应；状态文案与标签由它决定。

    5.9 缓存与快照标注规则

    • 实时源（汇率、天气）：cache: "no-store"，不写本地缓存，失败不回填。
    • 官方快照（政策、故宫）：把内容与 checkedAt、pageDate 一起打包，界面必须显示核对日期。
    • 区间估计（预算）：显示"区间估计"标签与核对日期，不写"实时"。
    • 任何快照过期（例如超过约定核对周期）时，正确做法是降级为"仅官方链接"，而不是继续当结论展示。

    6. 可信机制

    可信不是形容词，是每条结论固定带四件套 + 一个免责：

    1. 来源名：中文机构名 + 英文名（例：国家移民管理局 · Visa-Free Transit Policies）。
  • 原文链接：直达官方页面，不经过跳转站。
  • 查询时间 / 快照日期：实时写"查询 2026-11-05 18:31"；快照写"页面日期 2026-08-20 / 核对 2026-11-05"。
  • 适用范围：一句话限定"对谁、在什么条件下成立"（例：持 57 国普通护照、经 65 个指定口岸过境前往第三国）。
  • 免责声明：政策类固定写"官方快照，非实时法律意见；出行前以边检与使领馆现场认定为准"；实时类写"可能失败；失败时不给旧值"；地图写"真嵌地图需要 key，现在没有"。

    • 放置位置：

    • 结果气泡内 → 证据卡（可展开）→ 卡片内按"来源 / 原文链接 / 查询时间 / 页面日期 / 适用范围 / 免责"顺序排列。
    • 表格下方独立注释，重复来源与日期。
    • "数据说明"弹层集中列 9 个来源，口径与结果流一致。

    禁止表述：guaranteed entry、visa approved、definitely on time、把估计写成"实时"。

    • 移动优先：基准 390×844；单栏，对话占满，底部输入固定。

    7.4 语气

    短句、动词开头、不用感叹号堆情绪；英文与中文都避免"保证、绝对、官方认证"这类词。

    8. 状态机（答案变了，重算哪些结论）

    五个答案不是孤立表单，而是结果流的输入。改任一答案，整条结果流按新答案重建，同时保留证据卡与表格的引用关系。

    改变的问题重算不重算
    目的地城市匹配 → 天气请求、地址卡与坐标、预算语境、汇总条签证判定、证件入口、汇率
    到达时间汇总条、行前紧迫度文案天气（仍取当前）、签证、预算
    停留天数签证判定（≤10 天 / >10 天）、汇总条天气、汇率、地址卡
    护照签证判定（已核对名单 / 未核对）、汇总条天气、汇率、预算、地址卡
    想要什么是否追加"交通（12306）""求助（12308）"结论签证、天气、汇率、预算

    判定优先级：

    1. 护照未知 → unverified，不进入条件性结论。
  • 护照已知且天数 > 10 → likely（240h 不适用，指向 30 天名单/签证）。
  • 护照已知且天数 ≤ 10 → conditional，列出仍需满足的条件。
  • 天数未知 → 也按 unverified 处理，不猜。

    • 重算的副作用：

    • 目的地变更会重新发一次天气请求；旧请求未返回时不采用旧城市结果。
    • 改答案期间输入禁用；完成后恢复。
    • 结果气泡按固定顺序重建：入境 → 天气 → 汇率 → 预算 → 开放时间 → 证件 → 地址 →（交通）→（求助）→ 翻译提示 → 汇总。
